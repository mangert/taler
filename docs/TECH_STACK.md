# Технологический стек

## Общий подход

Проект разрабатывается на TypeScript для фронтенда и бэкенда. Единый язык уменьшает количество переключений между технологиями, упрощает обмен типами и делает кодовую базу удобнее для сопровождения.

## Фронтенд

- **React** — компонентный пользовательский интерфейс.
- **Vite** — локальная разработка и production-сборка.
- **TypeScript** — строгая типизация компонентов и данных API.
- **React Router** — маршрутизация между страницами.
- **TanStack Query** — запросы к REST API, кеширование, пагинация и обработка состояний загрузки.
- **React Hook Form + Zod** — формы и клиентская валидация.
- **Material UI** — адаптивные таблицы, формы, диалоги и навигация.
- **Recharts** — круговая и линейная диаграммы дашборда.
- **Papa Parse** — чтение CSV и предварительное сопоставление колонок.
- **Vitest + React Testing Library** — unit- и компонентные тесты.

Отдельный SPA-клиент выбран вместо SSR-фреймворка: поисковая индексация проекту не требуется, а REST API реализуется самостоятельным сервисом.

## Бэкенд

- **NestJS** — модульный REST API на TypeScript.
- **Prisma ORM** — схема данных, миграции, запросы и seed-данные.
- **PostgreSQL** — основная реляционная база данных.
- **class-validator / class-transformer** — проверка и преобразование входных DTO.
- **Swagger (`@nestjs/swagger`)** — автоматически создаваемая интерактивная OpenAPI-документация.
- **JWT (`@nestjs/jwt`)** — аутентификация и защита маршрутов.
- **Argon2** — хеширование паролей.
- **`@nestjs/schedule`** — создание повторяющихся транзакций по расписанию.
- **csv-parse** — окончательный разбор и серверная валидация импортируемых CSV-файлов.
- **Jest + Supertest** — unit- и интеграционные тесты API.

Денежные значения хранятся в PostgreSQL как `NUMERIC`, а снимки значений до и после изменения для журнала аудита — как `JSONB`. Изменение основной сущности и запись аудита выполняются в одной транзакции базы данных.

## Инфраструктура и качество кода

- **Docker и Docker Compose** запускают frontend, backend и PostgreSQL одной командой.
- **GitHub Actions** выполняет линтинг, проверку типов и тесты.
- **ESLint и Prettier** обеспечивают единый стиль TypeScript-кода.
- **npm** используется для управления зависимостями и запуска скриптов.
- Конфигурация передаётся через переменные окружения; секреты не хранятся в Git.

На первом этапе проекту не требуются Redis, очередь сообщений, микросервисы или отдельный сервис планировщика. Для дипломного демо достаточно одного экземпляра NestJS и встроенного планировщика.
