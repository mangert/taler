# Временный план настройки skills

> Рабочая заметка на следующую сессию. После переноса актуальных решений в постоянную документацию файл можно удалить.

## Итоговая рекомендация

Для Taler нужен небольшой набор проектных skills, привязанных к принятому стеку и требованиям диплома. Четыре skills стоит создать специально для репозитория, а два официальных Prisma skills — установить из `prisma/skills`. Больший набор пока не нужен: избыток пересекающихся инструкций усложнит выбор подходящего skill и будет расходовать контекст.

## Основной набор

### `tdd-workflow`

- Вести разработку поведения через короткий цикл: падающий тест → минимальная реализация → рефакторинг → повторная проверка.
- Backend: Jest и Supertest; frontend: Vitest и Testing Library.
- Каждый новый API-эндпоинт обязательно покрывать Supertest-тестом.
- Не требовать TDD для документации, сгенерированных Prisma-миграций и чисто конфигурационных изменений.

### `api-design`

- Зафиксировать правила NestJS REST API: DTO, валидация, Swagger, единый формат ошибок, фильтрация и пагинация.
- Для защищённых операций проверять JWT и принадлежность данных пользователю.
- Учитывать атомарность бизнес-операций и аудит изменений.
- При изменении контрактов обновлять документацию API и клиентские типы.

### `frontend-patterns`

- Описать архитектуру React + Vite SPA с TypeScript strict mode.
- Использовать TanStack Query для серверного состояния, React Hook Form + Zod для форм, MUI для интерфейса и Recharts для графиков.
- Не выполнять прямые запросы из UI-компонентов; выносить работу с API в отдельный слой.
- Проверять адаптивность, доступность, состояния загрузки, ошибок и отсутствия данных.

### `verification-loop`

- Перед завершением задачи просматривать diff и запускать релевантные тесты.
- Затем выполнять lint, typecheck, полный набор тестов и build, если команды уже доступны.
- Для инфраструктурных изменений проверять `docker compose`; для UI — выполнять smoke-проверку в браузере, когда это применимо.
- Сообщать только реально выполненные проверки и их результат, не подменяя проверку предположением.

### Официальные Prisma skills

- `prisma-client-api` — актуальные паттерны Prisma Client: CRUD, связи, фильтры, пагинация и транзакции.
- `prisma-cli` — команды Prisma CLI, генерация клиента, миграции и seed, включая актуальные особенности Prisma 7.

Планируемые команды установки:

```sh
npx skills add https://github.com/prisma/skills --skill prisma-client-api
npx skills add https://github.com/prisma/skills --skill prisma-cli
```

Перед установкой следует проверить, что skills добавляются локально в репозиторий, а не глобально.

## Что отложить

- Отдельные NestJS, Docker, GitHub Actions и architecture skills пока не нужны: их требования покрываются `AGENTS.md`, документацией проекта и четырьмя основными workflows.
- Отдельный security skill можно создать перед реализацией JWT, если проверок в `api-design` окажется недостаточно.
- `web-design-guidelines` пригодится позднее для ревью интерфейса и доступности.
- `playwright-cli` стоит добавить перед созданием сквозных smoke/E2E-тестов.
- `anthropics/skills@webapp-testing` не использовать: он опирается на Python, который не входит в выбранный стек проекта.

## Порядок действий на следующей сессии

1. Прочитать инструкции `skill-creator` и `skill-installer`.
2. Создать четыре репозиторных skill в `.agents/skills/<skill-name>/SKILL.md` с узкими, непересекающимися триггерами.
3. Установить два официальных Prisma skills локально в проект.
4. Проверить структуру, метаданные и автоматическое обнаружение skills Codex; при необходимости перезапустить сессию.
5. Сверить все инструкции с `AGENTS.md`, `.codex/rules/default.rules` и `docs/TECH_STACK.md`, убрать дубли и противоречия.
6. Проверить `git diff`, не затрагивая пользовательские изменения в `REPORT.md`.

## Рассмотренные внешние варианты

- `obra/superpowers@test-driven-development` — качественный, но слишком жёсткий общий TDD-процесс для текущего проекта.
- `obra/superpowers@verification-before-completion` — сильная основа для проверки, однако проектный skill позволит точно зафиксировать наши команды и критерии.
- `addyosmani/agent-skills@api-and-interface-design` — полезный общий источник, но не учитывает NestJS, Prisma, tenant isolation и аудит Taler.
- React skills от Vercel полезны для производительности и композиции, но многие рекомендации ориентированы на Next.js/SSR, тогда как Taler использует Vite SPA.
